# Lesson authoring template

Copy the structure below into a new numbered topic directory. Replace all prompts with actual content before proposing the module. This file is a template, not an unfinished lesson in the course map.

## Lesson README

1. **Title and prerequisites:** link only to concepts already introduced.
2. **Outcomes:** three things learners can demonstrate afterward.
3. **Theory:** what the construct means, syntax, execution model and suitable uses.
4. **Example:** link to a compiling, commented examples.sol with explicit units and permissions.
5. **Trace:** list exact inputs, outputs and persistent state after each call.
6. **Pitfalls:** one or more realistic mistakes and their consequences.
7. **Practice:** link exercises, solutions, quiz and answers separately.
8. **References/navigation:** official documentation, previous module and next module.

## Exercise specification

For each of warm-up, application and challenge, state:

- Problem and prerequisite concepts.
- Required contract/function API and data types.
- Accepted input domain and units.
- Expected normal examples and boundaries.
- Rejection conditions and state that must remain unchanged.
- What is deliberately simplified.

## Quiz and answers

Write four questions testing understanding: an execution trace, a boundary, a design choice and a common misconception. Explain each answer rather than supplying only a letter.

## Validation

Compile all sources and add tests tied to specified behavior. Test at least one successful operation, one boundary and one meaningful rejection where applicable. Avoid claiming exhaustive coverage from those examples.
